# Telegram Engineering

**Создавайте Telegram-ботов с ИИ, который понимает продукт, а не только API.**

[![Проверки](https://github.com/Ikhdev1/telegram-engineering/actions/workflows/check.yml/badge.svg)](https://github.com/Ikhdev1/telegram-engineering/actions/workflows/check.yml)

Скилл для ИИ и практический набор для разработки Telegram-интерфейсов: rich-сообщения, меню, устойчивый бэкенд, доступ и админка в боте. Для нового проекта и точечных изменений в существующем — без навязывания другого стека.

[English](README.md) · [Быстрый старт](#быстрый-старт) · [Инструкция для ИИ](SKILL.md) · [Галерея](references/gallery.md) · [Рецепты](references/recipes.md) · [Проверки](docs/verification.md) · [Участие в проекте](CONTRIBUTING.md)

## Быстрый старт

```bash
git clone https://github.com/Ikhdev1/telegram-engineering.git
cd telegram-engineering
python -m pip install -r requirements-dev.txt -r examples/support-bot/requirements.txt
python scripts/check_skill.py --json
```

Запустите законченный пример бота **без токена и Telegram-аккаунта**:

```bash
cd examples/support-bot
python -m support_bot --offline-smoke
```

Для работы через ИИ установите скилл по инструкции ниже и напишите:

> Используй telegram-engineering. Создай бота записи с понятным меню и админкой внутри Telegram. Сначала уточни важные продуктовые требования, сохрани мой стек и проверь результат локально.

Основной язык скилла и демо-бота — русский; README также доступен на [английском](README.md). Для инструментов нужен Python 3.12+, но рекомендации применимы и к другим существующим стекам.

## Зачем этот проект

- **Нативный UX Telegram:** обычные и rich-сообщения, контекстные кнопки, «Назад»/«Отмена», личные ответы в группе и понятные ошибки.
- **Настоящие правила бэкенда:** владение объектом, отзыв роли, транзакции, повторы доставки и конкурентные действия.
- **Исполняемые примеры:** рабочий бот, локальный валидатор и сценарии проверки созданного ИИ кода, а не только текст промпта.
- **Честные доказательства:** офлайн-проверки dispatcher/БД и браузерных макетов отделены от живой доставки и вида в Telegram.

## Установка скилла

Нужен ИИ-агент с поддержкой файловых скиллов. Разместите каталог `telegram-engineering` с `SKILL.md` в настроенном каталоге навыков вашего агента. Например, стандартный каталог omp — `~/.omp/agent/skills/`; для другого агента используйте его документированный путь. Настройки агента, хуки и разрешения этот пакет не меняет.

Для чистой установки сначала соберите архив командой ниже и распакуйте **доверенный локальный** `telegram-engineering.skill` (это ZIP) в каталог навыков. Архив уже содержит верхний каталог `telegram-engineering`. Если там есть предыдущая версия, сначала сохраните её отдельно; не смешивайте версии и не перезаписывайте другие навыки. Начните новый чат/сеанс агента, если список скиллов кэшируется.

Пример запроса:

> Используй telegram-engineering. Создай бота записи на услуги с меню и админкой в Telegram. Сначала уточни только важные требования; токен я настрою локально.

Для существующего проекта:

> Используй telegram-engineering. В этом боте нужно исправить доступ к заявкам и обработку повторных нажатий. Сохрани текущий стек.

## Быстрый запуск проверок

Нужен Python **3.12+**. Команды ниже выполняются из корня пакета; `python` должен указывать на выбранное окружение проекта. Создайте виртуальное окружение, если используете его, и не обновляйте глобальные пакеты ради примера.

Полный набор `tests/`, `evals/` и CI находится в исходном архиве/checkout. В компактной установленной `.skill`-версии нет корневых тестов и evals: проверяйте `check_skill.py`, валидатор и включённый smoke примера; для всех команд раздела используйте исходный пакет.

```bash
python -m pip install -r requirements-dev.txt -r examples/support-bot/requirements.txt
python scripts/check_skill.py --json
python -m unittest discover -s tests -v
```

Проверка рабочего примера — из `examples/support-bot`:

```bash
python -m unittest discover -s tests -v
python -m support_bot --help
python -m support_bot --offline-smoke
```

Offline smoke вызывает настоящие обработчики aiogram и настоящую временную SQLite. Только Telegram transport заменяется явно включённой локальной сессией без сети. Это не имитация БД и не подтверждение живой доставки. Обычный запуск использует реальный Bot API; секреты настраиваются локально. Подробности и ограничения — в [README примера](examples/support-bot/README.md).

## Валидатор

```bash
python scripts/telegram_payload.py --help
```

Формат вызова для собственного **raw payload JSON**:

```bash
python scripts/telegram_payload.py --method sendMessage --file request.json --json
```

Exit codes: `0` — нет локально найденных ошибок, `1` — payload не прошёл проверку, `2` — ошибка вызова/файла/JSON. Поддерживаемые методы и точные границы проверки перечислены в [справочнике валидатора](references/payload-validator.md). Не используйте успешный результат как гарантию, что сервер Telegram примет разметку: права чата, динамические лимиты, текущий API и клиентский вид проверяются отдельно. Валидатор ничего не отправляет.

## Галерея

Откройте `assets/gallery/index.html` в браузере или запустите локальный сервер:

```bash
python -m http.server 8765 --bind 127.0.0.1 --directory assets/gallery
```

Откройте `http://127.0.0.1:8765/`. Порт можно заменить. Не останавливайте процесс, который уже занимает этот порт. Макеты объясняют расположение контента и переходы; права в браузерном демо — иллюстрация, не серверная авторизация.

## Сборка для переноса

Сборка выполняется из полного исходного каталога с именем `telegram-engineering` (скачанный `telegram-engineering-main` сначала переименуйте). `--kind source` отклоняет компактный установленный скилл без корневых tests/evals/CI. Output — отдельный подкаталог вроде `dist`, не корень исходников и не его родитель. Выбранные файлы проверяются на похожие на Telegram-токены и приватные ключи; это ограниченный защитный барьер, не универсальный сканер секретов.

```bash
python scripts/package_skill.py --kind skill --output dist
python scripts/package_skill.py --kind source --output dist
python scripts/verify_archives.py dist
```

- `.skill` содержит основной материал, инструменты, примеры и галерею.
- `-source.zip` дополнительно содержит тесты, evals и CI исходного репозитория.
- Локальное состояние проекта, `.env`, базы, сессии, кэши, `.git` и `dist` исключаются.
- Вывод содержит SHA256. Сборка воспроизводима при неизменных входных файлах; публикация не выполняется.

**Лицензирование:** лицензия пока не выбрана. Публичный доступ сам по себе не означает разрешение на распространение по MIT/Apache; перед распространением получите разрешение владельца. Секреты и рабочие базы никогда не добавляются в репозиторий.

## Точность и ограничения

- Документация скилла опирается на проверенный снимок **Bot API 10.3 / aiogram 3.31.0**. Это не обещание вечной актуальности: перед новой возможностью проверяйте текущий контракт метода и SDK проекта.
- Обычные сообщения и rich messages используют разные контракты; приватный ответ внутри группы не является редактированием публичного сообщения.
- Пример на SQLite рассчитан на один polling-процесс, а не распределённый сервис. Условия перехода на PostgreSQL/устойчивую очередь описаны в справочниках.
- Проверки пакета не требуют токена. Они не подтверждают вид в iOS/Android/Desktop, реальные платежи, live ephemeral delivery или работу продакшен-инфраструктуры.
- Скилл не даёт разрешение читать чужие аккаунты, отправлять массовые сообщения или включать платные функции. Токен, OTP, 2FA и session string не нужно присылать ИИ в чат.

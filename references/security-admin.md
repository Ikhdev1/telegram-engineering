# Доступ, роли, настройки и админка

## Раздели три вида прав

1. **Права Telegram-бота в чате:** publish/delete/restrict/invite/manage topics и т. п.; проверяются через актуальный Bot API и выданные ChatAdministratorRights.
2. **Права пользователя в продукте:** клиент/оператор/админ/владелец, конкретные объекты и область организации. Админ группы не становится автоматически админом продукта.
3. **Доступ к инфраструктуре/аккаунту:** токен, webhook secret, DB, Telegram session. Это секреты, не пункты массовой админской выгрузки.

Статус в Telegram, command scope, наличие кнопки и подпись callback — не заменители бизнес-permission. Проверяй на **каждом** пути: command, message/FSM, callback, scheduled operation и HTTP API. Запрещай по умолчанию, неизвестные роли не повышай автоматически.

## Вход в продукт

Предложи только необходимый режим: публичный; allowlist по numeric Telegram ID; одноразовое приглашение; заявка с одобрением. Для доступа по подписке уточни источник и истечение. Инвайт/deep-link — короткий серверный token с purpose, сроком и одноразовым погашением; account linking подтверждается сторонами. Не помещай пароль/ключ в `start` payload и не считай открытие ссылки доказательством владения внешним аккаунтом.

**Owner** задаётся через доверенный конфиг/секрет развёртывания numeric ID, без режима «кто первый нажал /start». Начальные значения проверяются на старте; пустой/невалидный owner не означает всем разрешено. Смена owner и аварийное восстановление — явно разрешённый оператором канал. Обычный admin не назначает другого admin, если это право не согласовано отдельно. Сохрани невозможность случайно удалить последнего владельца.

## Базовая матрица (адаптировать к brief)

| Действие | Клиент | Оператор | Админ | Владелец |
|---|---|---|---|---|
| Создать/читать заявку | Только свою | По правилам продукта | В своём scope | В своём scope |
| Обработать заявку | Своя разрешённая отмена | Только назначенную | Разрешённая очередь scope | Разрешённая очередь scope |
| Назначить оператора | Нет | Нет | Да, в scope | Да |
| Менять рабочие настройки | Только личные | Нет либо отдельное permission | Согласованный набор | Да |
| Выдать admin | Нет | Нет | Нет по умолчанию | Да |
| Экспорт данных/рассылка | Нет | Нет по умолчанию | Отдельное permission + подтверждение | По необходимости + подтверждение |
| Читать секреты | Нет | Нет | Нет | Не показывать токен в Telegram-админке |

Не копируй матрицу механически: если нет операторов/заявок, не создавай их. Для multi-tenant scope обязателен во всех запросах, включая поиск, экспорт, счётчик и callback. «Объект не найден/недоступен» не раскрывает существование чужой записи.

## Сценарии админки в боте

Минимум по фактической задаче:
- Рабочая очередь: фильтр → список с пагинацией → карточка → разрешённый переход.
- Пользователи/доступ: поиск numeric ID или выбор известного пользователя → текущая роль/scope → изменение → подтверждение → аудит. Username только подсказка для поиска.
- Настройки: текущее значение и область → валидированный ввод → preview старого/нового → сохранить или отменить. Версия защищает от одновременного редактирования.
- Журнал: кто, что, над каким объектом, когда, исход; фильтры по задаче. Не лей туда весь update, личную переписку и токены.
- Публикация/рассылка/экспорт, если запрошены: permission → preview → точные получатели/объём/стоимость → подтверждение → progress/outcome и возможность остановить задания, если это требуется.

Админские операции проводи в личке или другом явно ограниченном интерфейсе. Групповая общая кнопка с `selective=true` не защищает данные. Все admin callbacks повторно проверяют актуальные права, scope и объект; отзыв роли должен влиять и на уже присланные кнопки.

## Подтверждение и аудит

Для удаления, блокировки, выдачи роли, массовых действий и стоимости привязывай подтверждение к actor, action, target/scope, ожидаемой версии и сроку. Одноразовое погашение и изменение объекта — атомарны. Повтор/истечение показывают результат без повторного действия. Переход назад не исполняет команду. Перед подтверждением покажи реальные последствия; не полагайся только на красную кнопку.

Audit записывается вместе с бизнес-изменением: actor numeric ID, роль/scope, действие, object, безопасная разница, timestamp UTC, result и correlation id. Секретные значения помечай «изменено», а не сохраняй plaintext before/after. В аудите отказов не раскрывай чужие данные. Срок хранения/доступ согласуй; не добавляй сбор персональных данных «для аналитики» без задачи.

## Mini App и веб-админка (только когда нужны)

Frontend не авторизует сам себя. Передавай **raw `Telegram.WebApp.initData`** серверу и проверяй подпись по [официальному алгоритму](https://core.telegram.org/bots/webapps.md#validating-data-received-via-the-mini-app), срок `auth_date`, правильный bot/environment и защиту от replay по контексту. `initDataUnsafe`, клиентский user_id, localStorage role и URL-параметр `admin=true` недоверенные.

Для стандартной серверной проверки HMAC используй поддерживаемый валидатор выбранного стека, протестированный официальными векторами: key derivation через `WebAppData`, корректный data-check-string, constant-time comparison. Не подменяй её алгоритмом Telegram Login Widget: они различаются. После проверки выдай ограниченную серверную сессию; повторно проверяй RBAC/ownership на каждом endpoint. `initData` не даёт автоматически права админа.

В cookie-сессиях используй Secure/HttpOnly/SameSite и CSRF-защиту для мутаций; в token-подходе определи expiry/revocation и допустимые origins. CORS не является аутентификацией. Отдельную веб-админку не оставляй с общим паролем/admin:admin; используй подходящую существующую auth и минимальные права.

## Секреты

Токен и webhook secret раздельны; загружай из env/secret manager, `.env.example` только с пустыми значениями/фиктивными ID и `.env` в ignore. Telegram API URL содержит токен — редактируй URL в логах/ошибках. Не проси прислать token/OTP/2FA/session string в чат, не выводи их в диагностику. При реальном раскрытии сообщи о необходимости отзыва и замены; не меняй доступы без разрешения. DB-пользователь/backup/тома получают минимальные права.

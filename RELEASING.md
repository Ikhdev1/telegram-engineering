# Подготовка к публикации

Этот документ не выполняет публикацию. Remote, создание GitHub-репозитория, commit, push и лицензия — отдельные решения владельца.

## Перед первым публичным репозиторием

1. Выбрать имя/владельца репозитория и видимость. Локальный каталог навыка не обязан сам быть git-репозиторием.
2. Выбрать лицензию и убедиться в праве распространять включённый код и тексты. Пока `LICENSE` отсутствует, не называйте пакет MIT/Apache и не выставляйте такую метку в metadata.
3. Прочитать `.gitignore`; публикуются исходники, а не рабочие `.env`, SQLite, session-файлы, логи и `PROJECT_STATE.md`.
4. Выполнить команды проверки из [README](README.ru.md). Проверить пример без реального токена, валидатор и чистую упаковку.
5. Просмотреть source ZIP и SHA256 из packager. Архив не заменяет просмотр staged files при будущем commit.
6. В первом релизе точно написать границы: офлайн dispatcher/БД, иллюстративная галерея, локальный валидатор; live Telegram acceptance/rendering отдельно.
7. После создания репозитория проверить реальный hosted CI. Наличие `.github/workflows/check.yml` ещё не означает успешный запуск на Linux/Windows.

## Команды локальной сборки

Из корня исходного пакета:

```bash
python scripts/check_skill.py --json
python -m unittest discover -s tests -v
python scripts/package_skill.py --kind skill --output dist
python scripts/package_skill.py --kind source --output dist
python scripts/verify_archives.py dist
```

Также выполните тесты и `--offline-smoke` из `examples/support-bot`. `.skill` содержит устанавливаемые материалы, source ZIP — дополнительно корневые тесты/evals/CI. При обновлении устанавливайте согласованную полную версию, не оставляйте устаревшие helpers от прошлой.

Не присылайте токен бота или секреты хостинга для подготовки релиза. Любая live-проверка должна использовать отдельного разрешённого тестового бота и тестовые чаты, а не работающий клиентский сервис.

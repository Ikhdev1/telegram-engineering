# Проверка версии 2.0.0

Дата: **2026-10-26**. Это отчёт о выполненных локальных проверках, не гарантия отсутствия ошибок и не отчёт о подключённом продакшен-боте.

## Среда и команды

Основные проверки выполнены на Windows x64, **Python 3.13.12**, **aiogram 3.31.0**, PyYAML 6.0.3. Использовался явно выбранный интерпретатор проекта. Другой Python из PATH может иметь другой SDK; его версия не переносится на проект автоматически.

Из корня исходного пакета:

```bash
python scripts/check_skill.py --json
python -m unittest discover -s tests -v
```

Из `examples/support-bot`:

```bash
python -m unittest discover -s tests -v
python -m support_bot --help
python -m support_bot --offline-smoke
```

## Что исправлено по независимому review

- Пропуск поздней ошибки после 200 предупреждений валидатора: truncation теперь не превращает invalid payload в exit 0.
- Ошибочное отклонение Markdown code spans, неполные ReplyParameters, вложенные ordinary blockquotes и rich content model.
- Утечка имён anchor/entity в диагностике, lone surrogates и квадратичный обход entities. Прямой локальный probe на 10 000 entities занял менее секунды; это наблюдение, не универсальная производительность.
- Ошибочный лимит длины по escaped HTML source, который мог остановить бота на корректном длинном пользовательском тексте.
- Зависимость общего polling от успешной доставки экрана: post-commit/read-only delivery отделена от транзакционной обработки; best-effort явно описан.
- Проверки реального private chat, slash-путей в обращении, startup SQLite lock и корректные ограничения завершения на Windows.
- Секрет в canonical Bot API URL/заполненном `.env.example`, выход через Windows junction, пустой архив при output-ancestor, несовпадение имени skill и неполный source archive.
- Противоречивые доменные условия бронирования, payer/refund/XTR, согласования/расписания и удаления/продления членства.

Для галереи JavaScript проверен настоящим parser-ом Node; после браузерных переходов console errors отсутствовали, горизонтального переполнения страницы на проверенных ширинах не наблюдалось. Макет остаётся **иллюстрацией**, а не клиентом Telegram или серверной реализацией прав.

## Воспроизведение сборки

```bash
python scripts/package_skill.py --kind skill --output dist
python scripts/package_skill.py --kind source --output dist
python scripts/verify_archives.py dist
```

Packager фиксирует порядок/метаданные ZIP, исключает локальные runtime-файлы и проверяет выбранные файлы на похожие Telegram-токены/приватные ключи. Проверка архива читает integrity, состав, пути, затем извлекает **собственный доверенный** compact skill и запускает его checker. Это не sandbox для скачанного недоверенного кода и не универсальный секрет-сканер. SHA256 выводится сборщиком, а не встраивается в этот включённый в архив документ.

## Что не проверялось

- Живые отправки Bot API, actual ephemeral delivery и клиентский вид Telegram iOS/Android/Desktop.
- Настоящие оплаты, возвраты, инвайты, изменение членства, публикации в каналы и production deployment.
- GitHub-hosted CI: workflow настроен для Windows/Linux и Python 3.12/3.13, но до публикации не запускался на GitHub.
- Статистическое превосходство скилла: один исполнитель на сценарий и одиночные routing-решения не дают такого вывода. На SQLite code-generation задаче старая версия уже проходила все проверки.
- Лицензия и права публичного распространения: выбор лицензии оставлен владельцу, remote/commit/push не выполнялись.

Реальный бот должен пройти отдельную live-проверку с разрешённым тестовым токеном и чатами. Токен, OTP, 2FA и session string не нужно передавать в переписке.
